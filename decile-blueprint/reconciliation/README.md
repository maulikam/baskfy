# `reconciliation/`

Committed evidence from Prompt 19, regenerated by two commands and asserted by tests.

| File | Command | What it is |
|---|---|---|
| `REPORT.md` | `make reconcile` | Every relationship docs/05 asserts between the reference export's published columns, re-derived through our own formula code, with tolerances propagated from docs/13 §4's storage precision. `services/worker/tests/test_reconcile_cli.py` fails if this file is stale. |
| `MUTANTS.md`, `mutants.json` | `make mutants` | Mutation testing of `decile_core.factors` and `decile_core.screener`. Survivors with no entry in `mutant-justifications.json` are a non-zero exit. |
| `mutant-justifications.json` | hand-written | `"<file>:<line>:<col>:<operator>": "why this mutant cannot be killed"`. Written by a human after reading the mutant, never generated. |

Two things these files do **not** establish, stated here because the tables above look more
conclusive than they are:

* `REPORT.md` reconciles the export against *itself* through our formulas. It does not recompute a
  single factor from price history — the repository has none. `make reconcile` grows a `--bars`
  argument for that, and it has never been run against real bars.
* `MUTANTS.md` scores the two modules against a *scoped* test selection (see
  `tools.mutation.TEST_SELECTION`), not the whole suite. A mutant that only the API tests would
  catch is scored as surviving here.
