# Gates: 1.1.5 Reverse bridge — Baskfy owns the login, the desk gets the session

Scope: Maulik has decided Baskfy keeps the Kite redirect. The desk still places every live order
and must rebalance on Friday 4 Sep, so it needs the session Baskfy's login produces.

Leaf 1.1.1 established why this is not trivial, and each point must be handled or ABANDONed:
 (a) it needs a WRITE path onto the trading box, inverting M58's read-only forced-command design;
 (b) the DEPLOYED desk stores its token as plain JSON, not repo HEAD's Fernet — the deployed
     desk is not at HEAD, so the on-disk format must be confirmed before writing;
 (c) `app/main.py:133-142` caches `_kite` and `kite_client.py:42` loads the token only in
     `__init__`, so a file written at 09:00 is NEVER picked up by the long-lived console that
     places Friday's orders. A write alone does not solve this.

WHAT WAS BUILT, in one sentence: the bridge carries the **request token** to the desk and lets the
desk exchange it — because `/callback` calls `kite().exchange_token(...)`, which mutates the
cached client in place, which answers (b) and (c) at once and makes (a) a *narrower* capability
than the M58 leg it sits beside. Two delivery paths, sharing the desk's existing `/callback`: a
Caddy 302 for the browser, and an SSH forced command for server-to-server. Full record in
`docs/DESK-LOGIN-DECISION.md` §9 and `docs/DECISIONS-MERGE.md` 1.1.5.
